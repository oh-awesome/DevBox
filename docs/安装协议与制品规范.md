# DevBox 安装协议与制品规范

> 面向：制品打包方、manifest 维护方、DevBox 应用侧。
> 本规范是语言运行时与工具制品的唯一安装协议：应用侧完全按 manifest 声明执行，零硬编码、零推测。manifest 顶层 `schema_version` 固定为 1（版本戳）。

## 一、制品规范

原则：**制品只负责"一个能跑的解释器 + 官方引导能力"，所有环境编排（裸名、PATH、链接链、current）交给安装协议执行。**

### 1.1 打包布局

```
python-3.12.15-ohos-aarch64.tar.gz     ← 固定命名：{name}-{version}-ohos-{arch}.tar.gz
└── python-3.12.15-ohos-aarch64/       ← 必须有且仅有一个根目录（外壳），normalize 步骤会上提
    ├── bin/
    │   ├── python3.12          ← 版本化实体（必需）
    │   ├── python3.12-config   ← 版本化实体（必需）
    │   ├── python3.12m         ← 若有，同规则
    │   ├── pip3.12             ← 可选（有则带，无则由 ensurepip 步骤引导）
    │   └── pydoc3.12           ← 可选
    ├── lib/python3.12/
    │   ├── ensurepip/          ← 必需且完整（含 _bundled/*.whl）——pip 官方引导机制
    │   └── ...标准库...
    ├── include/ share/ ...
    └──（无任何裸名 python3/pip3，无 current，无 .devbox）
```

### 1.2 硬性要求（校验项）

| # | 要求 | 校验方式 |
|---|---|---|
| A1 | tar 单一根目录（外壳） | 解析 tar 首条目 |
| A2 | `bin/` 内实体全部为版本化名（含次版本号），无裸名 | ls bin |
| A3 | `lib/python{major.minor}/ensurepip/_bundled/` 存在且含 pip wheel | 目录探测 |
| A4 | `bin/` 实体权限位含 x（tar 保真）；符号链接以 symlink 条目保存，不得实体化 | tar 类型位 |
| A5 | manifest `provides` 与 bin 实际可提供的命令一致——provides 是可执行承诺 | 打包 CI 比对 |
| A6 | sha256 / size 与 Release 附件一致 | 发布 CI |
| A7 | 版本化实体能执行 `--version` 且输出与版本号一致 | 打包 CI 冒烟 |

### 1.3 制品不需要做的

- 裸名链接（python3 / pip3 / python / pip）——安装协议创建；
- 捆绑 pip 的 bin 入口——ensurepip 步骤引导（制品带 ensurepip 即可）；
- 任何 `.devbox` / 注册表 / PATH 写入——应用侧职责。

## 二、manifest `install` 段规范

### 2.1 通用规则

- **占位符词表（封闭集合）**：`{name}`、`{version}`（纯版本号，如 3.12.15）、`{major_minor}`（如 3.12）、`{kernel}`、`{prefix}`（= install.prefix 解析后）、`{home}`。词表之外的出现即 schema 错误。
- **每步必有**：`id`（包内唯一）、`action`（词表封闭）、`title`（UI 展示）、`weight`（进度权重）；`params` 结构由 action 决定。
- **步骤语义**：应用按序执行；步骤失败即中止并报告（`optional: true` 的步骤失败仅警告）。
- **幂等责任在应用**：同步骤重复执行必须无害（块标记、先删后建等由应用实现，manifest 不表达）。

### 2.2 action 词表（完整集）

| action | 必填 params | 语义 | 执行器要点 |
|---|---|---|---|
| `download` | `dest`（默认 `{home}/tmp/{name}-{version}.tar.gz`） | 从条目 `url` 下载 | 流式 + 进度回调 + 断点续传；url 来自条目级 |
| `verify_sha256` | —（用条目 sha256） | 校验上一步产物 | 失败删除产物并中止 |
| `normalize` | `from`（外壳目录名，缺省 = 自动探测单根目录） | 外壳上提：把 `<dest>/<外壳>/*` 移入 `<dest>` | tar 单根假设的兜底，A1 违例时靠它 |
| `extract` | `dest`（默认 `{prefix}`） | 解压 tar.gz 到 dest | 解压后自动执行 normalize |
| `chmod_bin` | `dir`（默认 `{prefix}/bin`） | 目录内实体加执行位 | tar 权限不保真兜底 |
| `symlink` | `link`、`to`、`relative`（默认 true）、`condition` | 建链接；condition 词表：`always` / `if_no_valid`（链接不存在或悬空才建——首版设活跃语义） | 应用负责先清旧链接（含悬空） |
| `link_bin` | `links`: `[{"from": "...", "to": "..."}]`（from 支持相对路径与占位符） | 逐对建链接到 PATH 目录 | from 须指向版本化实体或 `current/bin` 跟随链 |
| `ensurepip` | `bin`（默认 `{prefix}/bin/python{major_minor}` 实体名） | `python -m ensurepip --upgrade` 引导 pip | 仅 python 族；幂等；成功后 bin 出现 pip3.x，供后续 link_bin |
| `shell_rc` | `file`（默认 `{home}/.zshrc`）、`block_id`、`lines`: [] | 以标记块写入（`# >>> {block_id} >>>` / `<<<` 包裹），重复安装整块替换 | 必须 block_id——裸 append 会重复污染 |
| `exec_check` | `cmd`（绝对路径或 `{prefix}/bin` 实体名，不得依赖 PATH）、`expect_rc`（默认 0）、`expect_stdout_prefix`（可选） | 执行验证 | expect_stdout_prefix 用于验"装的就是这个版本" |
| `file_check` | `path`（占位符，**用 `{prefix}` 本次产物，禁 current**——铁律同 exec_check）、`expect`（默认 `executable`；词表：`exists` / `executable` / `elf`） | 文件系统级探测，**不 exec 命令本体** | 沙箱天然免疫——部署完整性从可执行性解耦（协议不要求应用环境=用户环境）。`elf` 档前置拦截"声明二进制实为脚本"的打包错误；缺文件 fail loud（expat 型声明与制品不符前置暴露）。选型：ELF 二进制用 exec_check（验到版本输出）；`#!` 脚本入口/脚本包装器用 `executable`（用户终端自会执行）；纯库包用 `exists`（指向 .so）或不声明 |
| `provision` | `tool`: `pip`\|`npm`\|`maven`、`config` | 装后首配源（仅用户无配置时写入） | 首配源逻辑协议化 |
| `remove_dir` | `target` | 递归删除目录 | uninstall 段使用 |

### 2.3 install 段完整示例（python 3.12.15，可直接做打包模板）

```json
"install": {
  "prefix": "{home}/usr/local/{name}/{version}",
  "steps": [
    { "id": "download",  "action": "download",  "title": "下载制品",   "weight": 30 },
    { "id": "verify",    "action": "verify_sha256", "title": "校验完整性", "weight": 5 },
    { "id": "extract",   "action": "extract",   "title": "解压部署",   "weight": 25,
      "params": { "dest": "{prefix}" } },
    { "id": "chmod",     "action": "chmod_bin", "title": "执行权限",   "weight": 5,
      "params": { "dir": "{prefix}/bin" } },
    { "id": "current",   "action": "symlink",   "title": "版本切换链接", "weight": 3,
      "params": { "link": "{home}/usr/local/{name}/current", "to": "{version}",
                  "relative": true, "condition": "if_no_valid" } },
    { "id": "ensurepip", "action": "ensurepip", "title": "引导 pip",   "weight": 7,
      "params": { "bin": "{prefix}/bin/python{major_minor}" } },
    { "id": "linkbin",   "action": "link_bin",  "title": "链接全局命令", "weight": 10,
      "params": { "links": [
        { "from": "../python/current/bin/python{major_minor}", "to": "{home}/usr/local/bin/python3" },
        { "from": "../python/current/bin/python3",             "to": "{home}/usr/local/bin/python" },
        { "from": "../python/current/bin/pip{major_minor}",    "to": "{home}/usr/local/bin/pip3" },
        { "from": "../python/current/bin/pip3",                "to": "{home}/usr/local/bin/pip" }
      ] } },
    { "id": "env",       "action": "shell_rc",  "title": "配置环境变量", "weight": 5,
      "params": { "block_id": "ohpcd devenv", "lines": [
        "export PATH=$HOME/usr/local/{name}/current/bin:$HOME/usr/local/bin:$PATH"
      ] } },
    { "id": "check",     "action": "exec_check", "title": "版本验证",   "weight": 5,
      "params": { "cmd": "{home}/usr/local/{name}/current/bin/python{major_minor} --version",
                  "expect_stdout_prefix": "Python {major_minor}." } },
    { "id": "pipcheck",  "action": "exec_check", "title": "pip 验证",   "weight": 3, "optional": true,
      "params": { "cmd": "{home}/usr/local/{name}/current/bin/python{major_minor} -m pip --version",
                  "expect_stdout_prefix": "pip" } }
  ]
}
```

### 2.4 activate 与 uninstall 段（多版本共存协议）

安装（install）、切换活跃（activate）、卸载（uninstall）是三个独立操作，manifest 分别声明：

```json
"activate": {
  "steps": [
    { "id": "relink",  "action": "symlink", "params": { "link": ".../current", "to": "{version}", "condition": "always" } },
    { "id": "heal",    "action": "link_bin", "params": { "links": [ "...同 install 的 current 跟随链..." ] } }
  ]
},
"uninstall": {
  "on_last_removed": "clear_current_and_block",
  "auto_activate": "highest_remaining",
  "steps": [ { "id": "rm", "action": "remove_dir", "params": { "target": "{prefix}" } } ]
}
```

- `auto_activate: highest_remaining`：卸载活跃版本后自动切换到剩余最高版本；
- `on_last_removed: clear_current_and_block`：全部卸载后清 current 链接并删除标记块。

## 三、发现服务配合

发现服务只做存在性 + 入口 + 指纹，细节全部在 manifest：

1. `catalog_fingerprints`（两步零流量协议）：应用携带本地指纹查询增量，命中则跳过下载；
2. manifest 文件以 blob_sha 直连获取（发现服务返回 sha，应用按 sha 取内容）；
3. `runtimes.{name}.latest` 指针（可选）：推荐默认安装版本，减少应用侧"取最大版本号"的推断。

## 四、平台侧配合事项

| 事项 | 说明 |
|---|---|
| 存量制品整改 | 按第 1 节布局校验 A1-A7；违反 A5（provides 与 bin 不一致）的条目需重打包 |
| manifest 覆盖 | 各语言包族（python / BiShengJDK / node / rust / lua / perl / php / go）install / activate / uninstall 三段齐全 |
| CI 校验 | 占位符词表 + JSON Schema 发布，CI 校验所有条目合规 |

## 五、应用侧执行边界

- EnvStore 解析并保留 `install` / `activate` / `uninstall` 段原文；
- 安装统一走协议执行器（switch(action) 按词表实现），语言特判逻辑仅保留为自愈层（存量修复，不参与首次安装路径）；
- 执行器语义详见《架构设计》第 7 节。
