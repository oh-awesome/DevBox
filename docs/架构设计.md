# DevBox 架构设计

> 基线：v2.0.0。本文档描述 DevBox 的实现结构：分层、执行模型、数据层、安装链路与后台服务。
> 功能定义见《产品需求文档》，制品契约见《安装协议与制品规范》。

## 1. 总体结构

```
┌─ UI 层 ────────────────────────────────────────────────┐
│ pages/（17 个页面） + common/component.ets（Dev* 组件库）  │
│ DevTheme 双模式 token；@StorageProp('themeMode') 响应锚  │
├─ 服务层 ───────────────────────────────────────────────┤
│ RuntimeMgr（语言页公共件）/ PkgInstallFlow / 各 *Service  │
│ DevTask / TaskQueue / DevDownload / DevGateService      │
├─ 安装与数据层 ──────────────────────────────────────────┤
│ DiscoveryService → EnvStore（manifest/注册表/缓存）       │
│ → DevEnvInstall（协议执行器）→ DevEnvHeal（自愈层）       │
├─ Native 层 ────────────────────────────────────────────┤
│ libdevbox_native.so：forkpty 命令执行 + tar/gzip/xz 解压 │
├─ 后台进程 ─────────────────────────────────────────────┤
│ TrayAbility（独立进程）：系统托盘 + 后台任务续跑           │
│ └─ McpServer :18765（47 Tools，供外部 AI 应用调用）       │
└────────────────────────────────────────────────────────┘
```

## 2. 技术栈与工程结构

- **语言/框架**：ArkTS + ArkUI；单 `entry` 模块；
- **SDK**：OpenHarmony SDK，API 26（`compatibleSdkVersion/targetSdkVersion = 26.0.0`）；
- **UI 组件库**：IBest-UI-V2（表单类控件）+ 自研 Dev* 组件库（`common/component.ets`）；
- **Native**：C++（NAPI），`cpp/` 下编译为 `libdevbox_native.so`，内置 third_party/xz；
- **构建**：DevEco Studio / hvigorw（`assembleHap`）；依赖经 ohpm 安装。

目录速览：

| 路径 | 内容 |
|---|---|
| `entry/src/main/ets/pages/` | 17 个页面（Index 应用壳 + 16 功能页） |
| `entry/src/main/ets/common/` | DevTheme token、Dev* 组件库 |
| `entry/src/main/ets/utils/` | 服务层与数据层（30 个模块） |
| `entry/src/main/ets/mcpservice/` | MCP 服务器与工具注册 |
| `entry/src/main/ets/backgroundability/` | TrayAbility 托盘进程 |
| `entry/src/main/cpp/` | Native 模块（shell 执行 + 解压） |
| `test/ui_automation/` | 真机自动化测试（视觉模板匹配 + MCP 真值双通道） |

## 3. Native 层（libdevbox_native.so）

ArkTS 经 NAPI 调用，提供两组能力。

### 3.1 命令执行

| 接口 | 语义 |
|---|---|
| `execSync(cmd): string` | 同步执行，返回 stdout；用于短命令探测 |
| `execDirectSync(cmd, interpreter)` | 指定解释器直执行 |
| `execAsync(cmd, onOutput, onExit): handle` | 异步执行，输出行经 TSFN 回调主线程 |
| `cancel(handle)` | 原子取消标志置位，worker 线程 kill 子进程 |

实现要点：

- 每次调用独立 `forkpty()` → `sh -c` → `waitpid()`，不共享 PTY 会话（HMDFS 下会话管理不可靠）；
- worker 线程不能直接调 NAPI，输出经 `napi_threadsafe_function` 调度回主线程；
- `$$`（shell PID）每次执行不同，禁止跨命令拼路径；
- forkpty 后台进程无法触发系统安全弹窗——需要系统交互的流程必须回主进程执行。

### 3.2 解压（NativeExtract）

C++ 实现 tar / tar.gz / tar.xz 解压，零 shell 依赖：

- 接口 `extract(archivePath, destDir, format)` 返回 Promise 错误码（0 = 成功）；
- gzip 走系统 zlib 流，xz 走内置 decode-only liblzma（third_party/xz）；format 支持 `tar.gz` / `tgz` / `tar.xz` / `txz` / `tar` / `auto`（按魔数嗅探）；
- tar 解析器覆盖 POSIX ustar / GNU tar / BSD tar (pax)：长路径、长文件名、pax 扩展头、符号链接/硬链接、base-256 超大 size；
- 路径安全：拒绝 `..` 穿越与绝对路径，拒绝经符号链接写逃逸。

## 4. 命令执行与 shell 使用边界

文件与目录操作已全部原生化（fs API + NativeExtract），shell 仅用于两类不可替代场景：

| 场景 | 示例 | 原因 |
|---|---|---|
| 外部工具链命令 | `pip install`、`npm ls -g`、`brew install`、`conan install`、`go install` | 包管理器自身逻辑必须由其可执行体完成 |
| 安装验证 | `{prefix}/bin/python3.12 --version` | 装的就是"能跑的二进制"，必须真实执行 |

工程约束：

- **禁管道**：`cmd | tail` 之类管道会吞掉退出码，造成假成功；全仓命令不带管道，输出在 ArkTS 侧解析；
- **环境差异**：设备 shell 无 `awk`、`for` 循环、部分 `$(( ))` 算术展开；脚本兼容 POSIX 子集；
- **NO_COLOR**：conan 等命令 JSON 输出带 ANSI 色码，统一前置 `NO_COLOR=1` 并剥 `\x1b` 转义后再 `JSON.parse`；
- **密封执行环境**：brew 命令统一前置 `PATH=/usr/bin:/bin` + `Homebrew/bin/brew` 仓库实体路径，防止应用自带工具链对 brew 的 PATH 影子化。

## 5. 异步任务体系

| 模块 | 职责 |
|---|---|
| DevTask | 异步 shell 任务封装；`onDone` 回调 `detail` 为 `exit N`（退出码），非 stdout |
| TaskQueue | 三级队列（G1 交互关键 / G2 常规安装 / G3 后台维护）；出队调度、取消传播、队列面板数据源 |
| DevDownload | 下载统一走 `request.agent`；缓存键掺入制品 sha，断点续传 |

设计约定：

- 耗时操作必须异步：UI 线程同步执行超过 6s 触发系统看门狗 ANR——页面 `aboutToAppear` 禁止同步 execSync；
- 取消语义：busy 钮反转 + 下载断点记录；包级取消经 cancelTag 定位；
- finish 重入：任务完成回调内允许同步启动下一任务，清理动作在回调前完成；
- 磁盘预检：大件安装前 `statfs` 检查目标卷剩余空间；
- ETA：按当前步骤速率估算剩余时间。

跨进程互斥：MCP 触发的安装与应用内安装经 `filesDir busy.lock` + 心跳文件互斥，防止双入口并发写同一版本目录。

## 6. 数据层

### 6.1 安装注册表

每语言 `$HOME/usr/local/{name}/.devbox/` 下 registry JSON（active_version + versions{install_time, commands}）；Conan 全局账本 `$HOME/usr/local/.devbox/registry.json`。注册表是"已装什么"的唯一真值，活跃版本由 `current` 相对符号链接表达。

### 6.2 EnvStore

manifest 数据与可用版本列表的统一缓存层：

- 进程级缓存以 `runtime_epoch` 计数失效——任何安装/卸载动作 bump epoch，各页面缓存自动重查；
- 下载缓存键掺 sha，避免同名不同版本制品互相污染；
- 写文件前断开符号链接（`openSync(TRUNC)` 会跟随软链覆盖制品实体）。

### 6.3 配置文件

- `~/.zshrc` / `~/.bashrc`：标记块（`# >>> devbox xxx >>>`）整块读写，块外内容不动；
- `~/.pip/pip.conf`、`~/.npmrc`、conan 配置：结构化解析生成，写入前备份；
- 用户偏好（主题、首启提示、自定义文件表）走应用沙箱 preferences。

## 7. 安装链路

```
DiscoveryService（发现服务）
  └─ ohpcd.atomgit.com/api/discovery ──白名单──> catalog_fingerprints（本地缓存）
        └─ manifest blob_sha 直连获取（无指纹→空串，fail-loud + 30s 自愈）
              └─ EnvStore 解析 install/activate/uninstall 段
                    └─ RecipeParser → DevEnvInstall 执行器（11 action 词表）
                          └─ DevEnvRegistry 写入 + current 链接 + PATH 标记块
                                └─ DevEnvHeal 自愈层（存量修复）
```

- **协议执行器**：按 manifest 声明逐 action 执行（download / verify_sha256 / extract / symlink / link_bin / shell_rc / exec_check 等），应用侧不按语言硬编码安装步骤；manifest 语义详见《安装协议与制品规范》；
- **降级链**：发现服务 live → 本地缓存 → 内置种子；
- **自愈层**：语言特判逻辑（别名链修复、npm shim 治愈、ensurepip 引导）负责存量环境修复，与协议执行器互补——协议管首次安装，自愈管已装环境。

## 8. 目录服务（各包源）

| 服务 | 数据源 | 说明 |
|---|---|---|
| PyCatalogService | OHPCD 适配源 | 进程内解析，whl 文件名过滤（cp312/ohos/aarch64） |
| NpmCatalogService | npm registry | scoped 包名解析（`lastIndexOf('@')`） |
| ConanCatalogService | 社区 Conan 远程 | 进程内直连 + CDN 兜底（约 10k 包），离线缓存降级 |
| BrewCatalogService / BrewTapService | Harmonybrew formula 仓 + 多 tap | `list --versions --formulae` 文本解析（无 JSON 输出） |
| ArtifactsRepo | 制品仓 manifest | 语言运行时可装版本索引 |

所有目录服务统一"加载中/空/错误/缓存降级"四态输出。

## 9. MCP 服务

- **进程**：McpServer 实例运行在 TrayAbility 独立进程（与 UI 进程解耦，UI 退出后服务仍可用）；
- **传输**：HTTP JSON-RPC，`127.0.0.1:18765/mcp`，仅本机回环可达；
- **工具集**：47 个工具（`mcpservice/McpToolRegistry.ets`），按 L0-L4 分层——
  L0 环境感知与使用指导（get_context / devbox_help / check_env_gate）；
  L1 查询（list_runtimes / get_runtime_status / catalog_search / list_tools / get_task_progress 等）；
  L2 安装/卸载（install_runtime / uninstall_runtime / switch_runtime / install_tool / pip_install / npm_install / conan_install 等）；
  L3 配置（pip_source_set / npm_registry_set / goproxy_set / sync_shell_env）；
  L4 brew 包管理（brew_install / brew_upgrade_all / brew_priority 等）；
- **安全（敏感操作强制设备确认）**：危险类工具（运行时/工具/包的卸载与切换，`requiresConfirmation` 分类的 9 个）在 `call()` 被服务端确认门拦截——**确认策略由 DevBox 定义，调用方无法绕过**（历史方案 confirm="true" 二段式等于调用方自证，已废除）。链路：McpConfirm 登记 pending → 系统通知（"其他"类别 + WantAgent）→ 用户点通知拉起 **ConfirmAbility 独立小窗**（不唤醒主应用）→ 确认/取消经管理通道 `confirm.approve/reject` 回传 → TrayAbility 执行/作废并撤通知；30 分钟超时自动过期。通知授权：MCP 开启时 `requestEnableNotification`（仅首有效），弹窗内 `openNotificationSettings` 按钮直达设置页；
- **管理**：顶栏 MCP 胶囊打开管理弹窗（开关、接入配置展示与复制）；UI 进程经本机管理通道（AdminServer，`127.0.0.1:18766`）向托盘进程下发控制指令（拉起/停止 MCP 服务、确认回传、状态同步）。

## 10. 后台进程与保活

- **TrayAbility**：独立进程（`backgroundability/`），`NEW_PROCESS_ATTACH_TO_STATUS_BAR_ITEM` 注册系统托盘；
- **与 MCP 开关联动**：开关持久化在应用首选项（`devbox_prefs` 的 `mcp_enabled`，**默认关闭**）。EntryAbility 启动读偏好——开才注册托盘并拉起 TrayAbility，关则本会话无托盘无后台进程；运行中启停走管理通道 `mcp.start/stop`（:18766），失败回退 Want action（`action.mcp.start/stop`），TrayAbility 执行并持久化（单一写源）；
- **托盘**：图标（黑白双 SVG 随系统深浅切换）、一级菜单挂子菜单结构、点击行为；图标注册是异步操作，完成回调确认后再展示菜单；
- **保活**：TrayAbility 独立进程经 `NEW_PROCESS_ATTACH_TO_STATUS_BAR_ITEM` 窗口附着常驻 + `startBackgroundRunning(DATA_TRANSFER)` 长时任务（`KEEP_BACKGROUND_RUNNING`，防退后台网络挂起，保障后台下载与 MCP 服务连续性）；hilog 按 pid 过滤观察该进程；
- **职责**：承载 MCP Server、安装后台任务续跑、托盘快捷操作入口。

## 11. 环境前置门

DevGateService 为提醒模式：系统级检测通道（开发者模式状态、非市场扩展状态查询）在当前系统版本不可用，`check()` 恒返回放行；两项前置条件以总览页提示 + "关于"页分步教程表达，提供直达系统设置的深链：

- 开发者模式：`settings.openAboutDeviceSettingsPage`（官方 API，PC 26+）；
- 非应用市场扩展：显式 Want（`com.huawei.hmos.settings` + `privacy_settings`，三要素齐全避免隐式路由弹应用选择器）。

EnvGate 类型与拦截架构保留，检测通道可用后可在 `DevGateService.check()` 恢复。

## 12. 平台约束备忘

1. HMDFS 下 `cp -r` 可能丢文件——批量复制逐文件 + 校验 + 重试补偿；
2. shell 的 `$$` 每次执行不同，不可跨命令引用；
3. forkpty 后台进程无法触发系统安全弹窗，系统交互回主进程；
4. ArkTS 严格模式：禁 any/unknown、delete、解构赋值；ESObject 同样被 lint 拦截；JS 桥 require 系统模块会 crash（ESM import 可编译但 settings.getValue 对三方应用挂起）；
5. `@Prop` 单向绑定为浅比较，布尔 true→false 状态回退不触发重渲染（双活跃状态曾因此不同步）；
6. 装机验证必须比对 `updateTime`（`install -r` 签名不一致时静默失败，安装完成回调会正常返回）；
7. 应用侧 HOME 固定 `/storage/Users/currentUser`（hdc shell 视角不可见的路径，勿以 shell 判定存在性）。
