# DevBox 权限说明

> DevBox 是 HarmonyOS PC 上的开发者环境管理工具：在图形界面完成 Python / Java / Rust / Node.js / Lua / Perl / Go / PHP 等语言运行时与 60+ 开发工具的安装、多版本切换、卸载，管理 pip / npm / brew / conan 包生态，编辑环境变量与镜像源，并提供本机 MCP 服务供 AI 应用操作开发环境。
>
> 本文以 `entry/src/main/module.json5` 的 `requestPermissions` 与签名 profile 的 ACL 声明为准，逐项说明用途、必要性与不可替代原因。受限权限（system_basic / 受限 / kernel 级）不在普通申请范围内，须经签名 profile 的 ACL 通道授予。

## 1. 普通权限

### ohos.permission.INTERNET
- **用途**：制品下载、包目录查询（发现服务 / 制品仓 / pip / npm / brew / conan 源）、反馈提交。
- **必要性**：环境管理的一切数据（语言运行时制品、包索引）都来自网络，离线不可用。

### ohos.permission.KEEP_BACKGROUND_RUNNING
- **用途**：ContinuousTask 长时任务（DATA_TRANSFER 模式）——托盘进程保活，防止窗口关闭后网络被挂起，保障后台下载与 MCP 本机服务连续运行。
- **必要性**：`startBackgroundRunning` API 硬性要求（SDK `@permission` 标注）；大件工具链下载/安装在窗口关闭后必须继续，中断会留下半制品；MCP 服务承诺"应用关闭后 AI 仍可操作环境"，依赖后台常驻。

## 2. 受限权限（ACL）

### ohos.permission.READ_WRITE_USER_FILE（system_basic）
- **用途**：读写用户主目录 `~/usr/local/`（工具链安装根目录）与 `~/.zshrc` 等环境配置文件。
- **必要性**：安装 / 多版本切换 / 卸载 / 环境变量编辑四条核心链路的落盘目标全部在用户主目录。
- **不可替代**：沙箱目录内的文件对终端 shell 不可见——DevBox 装的环境必须在真实用户目录才能让用户在终端直接使用，这是"环境管理工具"的产品定义决定的。

### ohos.permission.CUSTOM_SANDBOX（system_basic）
- **用途**：使应用的终端子进程在用户卷 FUSE 上获得完整文件操作能力（含 symlink 创建）。
- **必要性**：多版本切换依赖 `~/usr/local/<name>/current` **相对符号链接**（鸿蒙 PC 开发者工具链协议，与华为内部 PolarisTerm 共用同一布局）。无此权限时子进程 symlink 系统调用被拒绝（实测 Permission denied），版本切换功能完全不可用。
- **不可替代**：实体拷贝方案会导致磁盘翻倍、文件一致性无法保证，且与 PolarisTerm 的互操作断裂；系统未提供其他 symlink 白名单通道。

### ohos.permission.FILE_ACCESS_PERSIST（system_basic）
- **用途**：持久化用户经系统文件选择器授权的文件访问权——环境变量模块添加**用户目录之外**的自定义配置文件（下载等公共目录、外接存储路径）后重启免重复授权。
- **必要性**：内置 `~/.zshrc` / `~/.bashrc` 凭 READ_WRITE_USER_FILE 直接读写；用户目录外路径不在其覆盖范围，选择器授权 + 持久化是唯一合规通道，每次启动重复弹窗不可接受。

### ohos.permission.READ_PASTEBOARD（system_basic）
- **用途**：环境变量编辑对话框的"从剪贴板粘贴"——把复制的配置片段 / 路径一键粘贴为变量值（多行自动拆分为多值）。仅读取、不监听剪贴板，用户点击粘贴按钮才触发。
- **必要性**：环境变量值常来自文档 / 终端复制的长路径与配置片段，逐段手动粘贴易错；一键粘贴是编辑效率的基本保障。

### ohos.permission.ALLOW_EXTERNAL_NATIVE_CODE（受限）
- **用途**：加载应用自带原生模块 `libdevbox_native.so`（forkpty 命令执行引擎 + tar/gzip/xz 解压引擎）。
- **必要性**：安装语言运行时必须真实执行其自带二进制（`--version` 验证）并解压 tar 制品；纯 ArkTS 无法执行外部进程。
- **不可替代**：所有安装链路的执行底座，无任何系统 API 可替代进程创建与 PTY 执行。

### ohos.permission.kernel.LOAD_INDEPENDENT_LIBRARY（内核级）
- **用途**：Python / Java / Node.js 等解释器与运行时按需 `dlopen` 自带动态库（如 Python 的 C 扩展、Java 的 native 库）。
- **必要性**：语言运行时离开动态库加载即无法启动；这些库由制品分带、路径不在系统默认搜索路径中。

### ohos.permission.kernel.ALLOW_WRITABLE_CODE_MEMORY（内核级）
- **用途**：JIT 型运行时（Node.js V8、BiShengJDK）运行中写入并执行代码内存页。
- **必要性**：JIT 是此类运行时的固有工作方式，关闭 JIT（解释模式）性能下降一个数量级，环境不可用。
- **不可替代**：系统对非市场分发二进制的代码内存默认保护策略需要该权限按需放行（真机验证：仅此一项即覆盖 Node/BiShengJDK 全链）。


## 3. 签名与验证

- 受限权限须经签名 profile 授予（DevEco 自动签名 profile 不含 ACL 族，须使用带 ACL 的 profile 重签）；
- 签发后用 hap-sign-tool 验证：`verify-profile` 输出的 acls 字段应与本文清单一致；
- debug 签名的应用只能在开发者模式开启的设备上安装运行（系统限制 17700052），关闭开发者模式的验证须用 release 签名。

## 4. 非权限类授权

- **自定义文件授权（环境变量模块）**：添加用户目录外的自定义 rc 文件时，经系统文件选择器（DocumentViewPicker）授权并持久化（见 FILE_ACCESS_PERSIST）。内置 `~/.zshrc`、`~/.bashrc` 凭 READ_WRITE_USER_FILE 直接读写，无授权流程；
- **下载目录访问**：仅下载功能写入公共下载目录，当前以应用沙箱路径为主。
